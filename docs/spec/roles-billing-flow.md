# Markor — роли, компании, предоплата и поток партии

Согласовано с владельцем 21.11.2026 (ответы на вопросы по одному). Это спецификация того, что строим в зоне `/aslbelgi` и `/admin`.

## Роли
- **Super admin** (`role = admin`) — владелец сервиса. Видит всех клиентов и все данные.
- **Registered user** (`role = user`) — клиент. Видит только данные своей компании.

## Компания
- При регистрации автоматически создаётся компания; пользователь — её владелец.
- Партии, коды, товары, баланс, платежи и тикеты принадлежат **компании** (`company_id`), а не человеку.
- Данные компании необязательны, клиент заполняет их позже в профиле: юр. название, СТИР/ИНН, адрес, телефон, банковские реквизиты. Понадобятся для будущей интеграции с Asl Belgisi (IZKM/OMS).
- Несколько сотрудников в одной компании — **позже, не сейчас** (структура данных уже готова).

## Регистрация
- Открытая: любой регистрируется (email + пароль) и сразу может загружать коды.
- Super admin может сам создать клиента (после звонка), редактировать его данные и сбросить пароль.

## Коды и загрузка
- Код маркировки **уникален во всей системе**. Код, который уже есть у любого клиента, не загружается и попадает в отчёт партии.
- Загрузка CSV — только через очередь: загрузить → в очередь → в базу → файл удаляется.

## Предоплата (биллинг)
- Цена: **9 сумов** за каждый загруженный код. Скидка по умолчанию 0%.
- **Бесплатный период:** при регистрации компании ставится дата `free_until` = сегодня + 1 месяц (`BILLING_FREE_MONTHS`). До этой даты включительно загрузка бесплатна, со следующего дня — оплата с баланса. Super admin продлевает на странице компании (+1/+3/+6 мес. от конца периода или от сегодня, если закончился; своя дата; «завершить сейчас»); клиент получает сообщение в Telegram.
- Цену и скидку по умолчанию super admin меняет в админке; у клиента может быть своя скидка.
- Цена и скидка фиксируются на партии в момент загрузки — смена цены не меняет старые партии.
- **Баланс компании** = подтверждённые платежи − списания за партии.
- Пополнение: клиент переводит деньги **на карту владельца** (без автоматизации), нажимает «Я оплатил» с суммой; super admin получает уведомление, подтверждает — баланс растёт.
- Партия списывается **целиком**. Если баланса не хватает — партия **заблокирована**: видна в списке, но нет доступа к кодам и PDF. Когда баланс покрывает сумму, партия **активируется** (коды получают статус «активен»).

## Поток партии
```
загрузка CSV → в очереди → загружается → загружена
  → (баланс?) заблокирована ⇄ активна
  → клиент просматривает коды и ПОДТВЕРЖДАЕТ партию
  → кнопка «Создать PDF» включается
  → PDF создаётся в очереди → «PDF готов» (уведомление; позже — отправка через Telegram-бот)
```
- До подтверждения кнопка «Создать PDF» выключена.
- PDF хранится и скачивается повторно; дизайн этикетки выбирает клиент.

## Удаление
- Клиент удаляет свою партию (через очередь), **только пока по ней не создан PDF**; списанная сумма возвращается на баланс.
- После создания PDF удалить партию может только super admin.
- Super admin также может аннулировать отдельные коды (например, испорченная этикетка) — их нельзя напечатать снова.
- В остальном super admin клиентские данные **только просматривает** (товары клиента не редактирует).

## Админка super admin
- Клиенты: список, использование, баланс, скидка; создание/редактирование клиента, сброс пароля, блокировка.
- Платежи: подтверждение «Я оплатил», ручная запись платежа.
- Настройки биллинга: цена за код, скидка по умолчанию, номер карты для перевода.
- Шаблоны этикеток (есть) + **тикеты** от клиентов на новый шаблон.
- «Мы предлагаем» — редактирование товаров в админке (3 языка) вместо сидера.
- Журнал действий (audit log): входы, загрузки, удаления, платежи, смены скидок.
- Сообщение всем клиентам (объявление в приложении; позже — через бота).
- Настройки сайта: телефон, Telegram, название компании, номер карты.
